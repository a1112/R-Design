# iPad native shell

The SwiftUI shell opens the same authenticated Bridge workbench in WKWebView. Enter your Bridge HTTPS address, then redeem the desktop-issued one-time pairing code in the web workbench. Native code receives no Bridge root token or provider key. HTTP is restricted to loopback for simulator development; use a TLS gateway for IP addresses or remote networks.

Enable Pencil after entering annotate mode. The web runtime exports `nativeTarget()` with the frozen frame's rendered CSS bounds, source pixel dimensions, frame ID and viewport width. The optional `viewport: {x,y,w,h}` reports the infinite canvas view bounds in CSS pixels. A separate clipped native container confines Pencil input to that viewport while PKCanvas retains the full transformed frame dimensions and offset. Camera panning moves the full canvas inside the clip; zoom and WK viewport resizing transform the same frame's drawing by its physical canvas size ratio, keeping shared source coordinates stable. Fully offscreen frames hide native input without clearing cached drawings. Finger gestures continue to reach the Web camera. Interpolated points are sampled in shared frame coordinates. Targets without `viewport` use the earlier full-frame overlay geometry. When `nativeTarget()` supplies optional `projectId`, raw PKDrawing is cached per Bridge origin/project/frame, so cloned frame IDs cannot share ink between projects. Returning to the homepage hides the native overlay and saves the previous project draft. Hosts without projectId retain the earlier single-project cache identity. Native drawing payloads include a known projectId and check it again before transfer. Raw PKDrawing is cached in protected Application Support files and included with shared Stroke samples. `交给批注` transfers to the Web annotation draft; the workbench save action persists a shared annotation. Native cache remains after disconnect. Clearing a native draft leaves shared annotations intact.

Run `xcodegen generate` in this directory. Build with `xcodebuild -project RDesign.xcodeproj -scheme RDesign -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/rdesign-ipad-build CODE_SIGNING_ALLOWED=NO build`. Run native geometry and PKDrawing cache tests with `xcodebuild -project RDesign.xcodeproj -scheme RDesign -destination 'platform=iOS Simulator,id=YOUR_IPAD_SIMULATOR_ID' -derivedDataPath /tmp/rdesign-ipad-build CODE_SIGNING_ALLOWED=NO test`. These cover viewport clipping, camera pan/zoom, CSS-to-WK scale changes and raw drawing cache round trips. For a device, choose your own Apple developer signing team in Xcode. `project.yml` is the project source; generated Xcode files are reproducible.

A simulator build does not verify real Pencil pressure, palm rejection, Chinese IME, rotation, split view, multi-window or input latency. These require real iPad acceptance testing. The iPad never installs project dependencies or executes build commands locally. App Store distribution and review remain separate.

## Connect a real iPad over TLS

The Bridge listens on loopback by default. The operator chooses a reachable hostname, a certificate valid for that hostname, its PEM private key, and one canonical HTTPS origin. Launch the desktop Bridge with `RDESIGN_HOST=0.0.0.0`, `RDESIGN_TLS_CERT=/absolute/path/bridge-cert.pem`, `RDESIGN_TLS_KEY=/absolute/path/bridge-key.pem`, and `RDESIGN_PUBLIC_ORIGIN=https://your-desktop.local:4310`. Keep key files outside the repository. Use your organization's or developer-managed trusted CA; a bare self-signed server certificate is not automatically trusted by WKWebView. If using a development CA, install and explicitly trust that CA on the iPad through [Apple's certificate trust settings](https://support.apple.com/en-us/102390): Settings > General > About > Certificate Trust Settings, after installing the CA profile. This shell does not bypass certificate errors.

On the desktop open `https://localhost:4310` (include localhost in the development certificate), obtain desktop authorization through local bootstrap, and create a one-time pairing code. On the iPad enter the same HTTPS origin, then redeem the code in the displayed pairing screen. Remote `/api/bootstrap` is denied; the code grants a revocable device session. Test revocation and disconnect before normal use. The exact hostname and certificate must agree, and both devices must have network access to the desktop port. Cross-network gateways must retain the same origin and authentication policy; raw agent/dev ports are not exposed by this workflow.
