# Independent Codex SDK worker

This optional local process implements the AgentProvider `/runs`, status, heartbeat and cancellation contract with the pinned `@openai/codex-sdk` dependency. Host-driven MCP tasks do not start it. No SDK run starts just by launching this server.

The operator supplies a dedicated server-side `OPENAI_API_KEY`, a random `RDESIGN_AGENT_WORKER_TOKEN` of at least 32 characters, and an explicit estimated `RDESIGN_AGENT_RUN_COST_CEILING_USD` for one implementation turn. Launch with `npm run worker`; it listens on `127.0.0.1:4320`. Set `RDESIGN_AGENT_WORKER_URL=http://127.0.0.1:4320` and the same worker token in the Bridge process, then restart Bridge. Host tokens and API keys never appear in workbench state, prompts, browser storage or MCP results. `RDESIGN_AGENT_MODEL` is optional and preserves an operator's explicit model selection. `RDESIGN_AGENT_MAX_BUDGET_USD` defaults to 2; max run duration defaults to 300000 ms through `RDESIGN_AGENT_MAX_DURATION_MS`.

Candidates must be existing directories below `RDESIGN_AGENT_CANDIDATE_ROOT` (default `.rdesign/candidates`). The Bridge derives confirmed intent, owner, candidate and allowed files. The worker records a run before SDK execution, blocks a concurrent project executor, checks candidate paths and private files, and rechecks all source hashes after execution. Out-of-scope edits produce a failed candidate, never acceptance. Bridge finalization creates a fresh diffHash and invalidates prior evidence; verification and explicit user acceptance still follow.

The SDK receives only an allowlisted subprocess environment and a fresh documented CLI configuration/session directory for each run. Its `apiKey` is explicit and `forced_login_method=api` prevents host login fallback. Generated commands receive no provider or worker keys through the configured shell environment. The configured permission profile denies root reads, allows minimal runtime/tool paths, grants candidate read/write and disables command network; CLI approval is `never` and web search is disabled. Current [official permission documentation](https://learn.chatgpt.com/docs/permissions) says legacy `sandboxMode` overrides permission profiles, so this worker uses the stricter candidate profile and never falls back to broad access. Profiles remain beta; unsupported or rejected policies fail the SDK run. For deployed workloads, use a dedicated worker service account or VM with only candidate data available. No live sandbox or paid SDK execution was used to validate this implementation.

Bridge heartbeats are independent of client connections. They renew the current generation while the worker is active; expired or cancelled leases cannot be renewed. Explicit cancellation aborts the SDK turn, fences old finalization and persists state. After a worker-process restart, interrupted runs are marked failed and their generations advance; inspect candidate diagnostics before submitting a new run. Journals and SDK thread IDs are saved under `.rdesign/agent-worker` and are not committed.

Budget control is named `estimated-preflight-ceiling`: the operator's one-turn estimate must fit the request budget and server ceiling. The SDK reports token usage; this implementation does not infer actual USD charges or promise a hard mid-turn dollar cap. Use provider project spending limits for hard billing controls. One implementation turn runs per request, below the approved iteration maximum; it does not endlessly repair. Tests inject a mock runner and never call billed providers.
