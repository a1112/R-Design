PRODUCT / 01
执行摘要：连接真实软件的设计工作台
不是“生成界面图片，再交给别人实现”，而是围绕同一个真实运行界面持续设计、修改和验收。
产品定位
R-Design 是面向 iPad 与桌面的 AI UI 设计工作台。以真实界面为观察对象，以手写与文字为设计输入，以源码变
更与运行验证为最终结果。
连接真实界面→ 选择与标注 → 提出修改 → 代码 / 资产变更→ 运行验证
三条产品主线
Live Canvas 实时画布
接入当前运行实例，实时同步画
面、控件结构和状态。保留与普通
设计画板、冻结快照的区别。
AI 设计与代码闭环
图像生成用于视觉方向与资产；确
定性属性编辑与 Codex 任务共同完
成真实 UI 修改。
跨端表达与审查
iPad 用笔表达，桌面接入项目和执
行环境。两端共享项目、批注、变
更和验收证据。
推荐形态
桌面优先交付 Codex 插件和完整 Web 工作台；iPad 使用原生外壳与共享 Web 主体；工作区桥接服务部署在授权
电脑或受控服务器。插件是入口，不是唯一的文档存储与运行引擎。
官方插件体系可以打包 Skills 与 MCP 服务，MCP 服务可选提供自定义 UI。本文以此为集成基础，但不同宿主的
展示与权限必须独立验证。 [01][02][03]
第一条必须打通的闭环
在 iPad 上圈出运行中的按钮，写“圆角 12，文字改为立即开始”；系统定位源码、产生最小变更、运行验证，
再把真实结果同步回同一个画板。

PRODUCT / 02
目标范围与能力分级
先保证自己的 Web 项目可持续迭代，再扩展更多软件框架。不要用“任意软件都可编辑”替代清晰的能力边
界。
需求编号 必须交付的能力 边界
FR-01 项目、页面、画板、资产和版本管理 项目文档可独立保存，不依赖聊天历史。
FR-02 运行实例的实时画面与结构同步 跟随同一实例，不用相同网址冒充同一状态。
FR-03 笔迹、文字框、对象批注与任务转换 自由笔迹不会自动触发代码执行。
FR-04 受控属性编辑与 Codex 复杂修改 持久化变更须经版本校验与验证。
FR-05 AI 风格方案、局部图像与资产生成 生成图不冒充已实现界面。
FR-06 源码差异、视觉差异、交互验证与回退 接受与推送、部署分别授权。
FR-07 页面状态目录与 UI 总览 覆盖已登记场景，不宣称穷举所有状态。
FR-08 跨端配对、离线批注与任务恢复 离线执行请求恢复后重验版本。
首版支持与延期项
首版完整闭环：React + TypeScript + Vite 的可修改开发项目；单用户多设备；一个受控执行者；桌面浏览器与
iPad 客户端；图像提供方可配置。
后续扩展：Tauri WebView、更多 Web 框架、原生窗口结构适配、多人协作、自托管团队 Worker、独立 Tauri 桌
面壳。
不在首版承诺：任意截图无损还原图层，任意框架双向无损转换，修改无源码软件的内部实现，iPad 本地完整桌
面开发环境。
两个独立维度
“本软件可运行在 iPad”与“本软件能生成原生 iPad 应用”不是同一个功能。首版输出目标是 Web UI；
SwiftUI 等输出必须另设适配与验收。

PRODUCT / 03
工作流：从想法、参考图或现有项目开始
三种入口进入同一套设计对象、任务和变更模型，不形成三套互不兼容的工程。
入口 主要步骤 应保留的事实
从想法开始 整理目标与页面结构 → 选择视觉方向 → 生成组
件与页面 → 接入预览
结构方案与风格方案分别确认，避免因为喜欢
配色而默认接受全部布局。
从参考图开始 导入图片 → 推断布局与组件 → 人工修正 → 重建
代码 → 验证
原图永久保留；推断结构标为重建结果，不声
称恢复原始图层。
从现有代码开始 授权工作区 → 启动或连接实例 → 采集结构 → 建
立源码关联
不重写全项目；优先保持业务逻辑、数据接口
与事件行为。
一次修改的完整体验
定位目标 → 确认理解 → 准备候选 → 执行与验证 → 审查接受
用户圈出设备卡片区并写：“桌面两列，间距 24，手机单列，卡片高度一致。”系统先生成修改理解卡，展示作
用范围、布局条件、保持不变项和验收场景。
理解卡字段 示例
对象 设备概览 / 设备卡片列表 / 当前实例与版本。
意图 桌面两列；窄屏一列；间距 24 CSS px；同一行等高。
约束 保留数据请求、点击跳转、错误状态和键盘可访问性。
影响范围 卡片容器和相关样式；不修改采集、通信或数据模型。
验收 指定桌面与窄屏场景截图；卡片点击与键盘聚焦测试。
默认修改候选实例
复杂变更在隔离候选工作区中执行。原实时画板继续代表基准实例；候选画板代表新代码。接受后才能更新长期
实现与基准版本。

EXPERIENCE / 05
iPad：原生笔输入与共享画布
iPad 不是缩小版桌面工具。画布优先，面板按需出现，手写不绕远端执行环路。
图 2 · iPad 交互布局示意。冻结的是观看帧，不是业务进程。
输入 / 工具 默认行为 必须避免
Apple Pencil 笔迹、圈选、箭头和草图；原生即时反馈每个笔采样都等待网络返回。
手指 / 触控板 平移、缩放、选择与标准交互 缩放时笔迹脱离控件或误触业务按钮。
界面文字 创建真实 Text 节点或提出文字属性修改与评论文字框使用相同对象类型。
文字批注 附着于对象或快照，经过确认转成任务输入一段评论就自动执行代码。
代码编辑 查看关联源码、修改文本、查看诊断与差异把 iPad 前端当成完整构建与执行环境。
建议外壳使用 SwiftUI / UIKit + WKWebView，手写使用 PencilKit。PencilKit 可读取与处理笔画等绘图数据，因
此建议保留原始数据，并派生跨平台笔迹格式。 [05]
真机验证范围
Apple Pencil 与手指冲突、中文输入法、软键盘、旋转、分屏、多窗口、压力采样、画布坐标变换。浏览器设备
模拟不能替代这些验收。

LIVE CANVAS / 06
统一画布模型与状态语义
让实时 UI 成为正式文档对象，而不是在画布里塞一个没有身份的远程视频窗口。
对象 权威来源 允许的主要操作
DesignFrame 结构化设计文档 布局、文字、组件与变量编辑；导出并重建代码。
LiveFrame 指定运行实例的当前画面与结构观察、交互、检查、对象批注；明确发起修改。
SnapshotFrame 不可变的时间点快照 测量、评论、视觉对比与证据存档。
CandidateFrame 候选工作区与其运行实例 验证、对比、继续修改、接受或丢弃。
ReferenceFrame 外部参考图或 AI 概念图 裁切、标注、视觉探索；不承诺原生图层。
LiveFrame 的三层结构
真实画面层
源软件实际呈现的像素或直接受控
渲染结果。负责图表、视频、特效
与自绘区域的真实展示。
控件结构层
节点身份、边界、层级、角色、样
式、源码映射与可编辑能力。负责
选择、命中、测量和修改范围。
操作与批注层
选框、笔迹、文字意见、属性预览
与差异标记。归属 R-Design，不注
入业务数据。
状态必须由事实驱动
状态建议包括：连接中、实时、延迟、重同步、只读、已冻结、待重载、构建失败、权限丢失、已断开。失去连
接后保留最后画面，同时标明过期时间并关闭远程输入。
不能混用的标记
显示成功不等于结构化可编辑；临时覆盖不等于保存源码；文件已写入不等于运行生效；运行生效不等于测试通
过。

ARCHITECTURE / 08
运行时接入等级与适配器契约
不同软件获得不同深度的能力。连接向导必须显示实际协商出的能力，而不是根据文件扩展名推断“全部支
持”。
等级 接入内容 可用能力
L1 画面 授权窗口、浏览器表面或图像流 实时观看、区域批注、冻结与比较。
L2 结构 控件树、命中、边界、角色或可访问信息对象选择、对象跟随、有限属性检查。
L3 源码 项目、组件标识、构建与源码映射 可靠上下文、受控属性回写、代码任务与验证。
拟定 RuntimeAdapter 能力
能力组 接口语义
发现与连接 discover / connect / disconnect；只枚举和连接用户授权范围。
采集 captureFrame / snapshotTree / subscribePatches；协商画面与结构支持度。
检查 hitTest / inspectNode / resolveSource；返回可靠等级和失效原因。
控制 dispatchInput / previewProperty；需输入租约和显式权限。
生命周期 onReload / onWindowChanged / health；窗口重建时更换会话世代。
Windows 可采用官方界面捕获 API；控件结构可以通过 UI Automation 获取，但其视图会过滤某些元素，不能当
成完整设计图层。 [13][14]
Tauri 在 Windows 与 macOS 使用不同 WebView 实现，因此建议先使用开发期接入包，再分别验证捕获、调试和
原生窗口路径，不假设 Chromium 协议跨平台通用。 [12]
自绘与特殊表面
Canvas、视频和 3D 视图可以作为整体画面显示；内部对象需要渲染器的命中与标识接口。弹出窗口、系统菜
单、遮挡、最小化和受保护内容分别检测，不能一律宣称可捕获。

ARCHITECTURE / 09
Web 采集：事件驱动、局部重算、真实呈现
首版优先接入自己可修改的 React 项目。为开发构建增加 Runtime SDK 与构建期标识插件，生产构建默认移
除。
变化来源 采集方式 实施要求
DOM 节点、文字、属性MutationObserver 只记录相关变化；先合并脏节点，再批量采样，避免逐事件
全量遍历。
尺寸变化 ResizeObserver 采集与样式写入分离，避免观察回调反复触发布局。
样式与主题 受影响区域样式采样 样式表、媒体查询、字体、伪元素和状态变化需要补充触
发。
滚动、缩放、视口 窗口和滚动状态监听 记录 visual viewport、滚动偏移、DPR 和坐标变换。
动画、Canvas、视频真实画面通道 结构只表达稳定容器，不尝试将所有像素转换成节点。
代码更新与页面重载 构建 / HMR 生命周期 标记候选版本、清理临时覆盖，重建映射或完整结构。
MutationObserver 观察 DOM 变化，ResizeObserver 报告元素尺寸变化，getComputedStyle() 用于读取解析后
的样式。它们是互补的采集基础，不等于完整的视觉变化监听器。 [06][07][08]

审查证据与接受基线不可自动覆

多执行者竞争 覆盖或重复应用 任务所有者、租约世代、幂等记录、串行接受。
生成质量不稳定 不满足设计要求 小范围生成、结构化约束、真实运行和人工审查。

IMPLEMENTATION / 31
端到端实施样例与交付检查
用一个可重复样例，把产品体验、数据协议、代码执行和验收规则串起来。
步骤 实施动作 保存证据
1 连接 选择开发项目与 dev-01；授权捕获和读取项目版本、会话、能力协商、首帧与结构。
2 选择 iPad 选中第三张设备卡片，冻结当前帧 runtimeNodeId、instanceKey、几何与快照
锚点。
3 标注 写“桌面两列，间距 24，手机单列” 原始笔迹、识别结果与确认后的意图版本。
4 准备 明确改容器而非业务数据，建立候选基准 文件哈希、范围、约束、场景和预算。
5 执行 由唯一执行者生成最小布局修改 AgentRun、补丁、资产、日志与错误。
6 验证 运行桌面 / 窄屏场景与点击测试 候选代码版本、实际截图、结构、测试结果。
7 审查 同时比较代码与视觉，确认卡片交互保留 接受人、diffHash、基准与审批记录。
8 接受 重验基准并应用；刷新受影响画板 新接受版本、映射重建与最新快照。
9 回退 创建反向变更并检查后续冲突 撤销结果与新的接受历史。
最小可交付版本的完成定义
可安装、可配对、可打开项目、可看到真实界面、可用笔批注、可定位源码、可生成候选、可运行验证、可比较
接受、可在失败时恢复。每一项都有保存的场景与测试证据。
项目最终应坚持的关系
源码决定长期实现，运行实例决定当前画面，画布承载设计意图与批注，ChangeSet 连接代码与证据。这四者清
楚分工，才有可靠的实时双向工作流。
本版未进行项目接入、插件安装、代码实现或真机性能测试。后续实现应把本文件转成可执行任务与测试，不把设计描述当成已完
成事实。
