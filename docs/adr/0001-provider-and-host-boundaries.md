# ADR 0001 — Bridge owns state; providers are explicit

Accepted for v0.1.

All MCP mutations use the authenticated Bridge and retain project revision and operation IDs. MCP stdout is reserved for JSON-RPC. No tools return root session tokens or provider credentials. Context tools return bounded trees, annotations and verified evidence. The complete browser workbench is the current host UI fallback.

Host-driven execution consists of the host calling `rd_prepare_change`, `rd_verify_change` and a reviewed `rd_apply_change`. The plugin never implicitly launches a second agent. Standalone AgentProvider connects only to a separately authorized worker at `RDESIGN_AGENT_WORKER_URL`, with server-only `RDESIGN_AGENT_WORKER_TOKEN`. It never reads Codex internal session data, user credential stores, or ambient host auth. The included optional SDK worker enforces candidate roots, source scopes, strict permission profiles, explicit preflight cost estimates and lease generations. Bridge must create and validate the candidate directory and derive confirmed intent from stored annotations.

The external worker contract uses authenticated `POST /runs` with the complete AgentStartRequest plus runId and lease, returning a persisted `{id}`; `GET /runs/:id` returns `{status,logs,result}`; `POST /runs/:id/cancel` receives `{generation}`. The Bridge independently polls active run status within the 60 second lease, even when a UI disconnects; its provider forwards `POST /runs/:id/heartbeat` with `{lease:{generation,expiresAt}}`. The worker rejects writes after expiry or cancellation; the Bridge does not grant a new lease to an expired executor. Worker cancellation must fence old writes. A request is journaled before dispatch. Uncertain dispatch blocks a second executor until reconciled. Persisted operation fingerprints reject changed replay payloads; project dispatch is serialized in one Bridge process. Multi-process deployment requires shared transactional leases and is not claimed here.

Image generation is opt-in. Server configuration requires `OPENAI_API_KEY`, `RDESIGN_IMAGE_MODEL`, `RDESIGN_IMAGE_COST_CEILING_USD`, and optional `RDESIGN_ASSET_MAX_BUDGET_USD` (default 1 USD). Each request requires `externalGenerationApproved: true` and approved `budgetUsd`; requests outside server limits or the configured ceiling are rejected before external calls. One low-quality 1024×1024 PNG is requested. The configured ceiling is an operator estimate, not measured spend; use provider project spending controls for a hard account cap. No silent account or provider fallback occurs. Imported references work without provider credentials.

Image operation journals precede external side effects and retain successful asset identity. Interrupted or rejected requests are not automatically replayed; operator reconciliation prevents possible duplicate charges. The same policy applies after a process restart. No billed provider calls are included in tests.

The native shell has no file/system execution bridge exposed to web content. Navigation stays within the selected workbench's main origin. Native Pencil overlay bounds come from that origin's top-level workbench API. Drafts are cached per frame and transfer into web annotation drafts; shared save remains a Bridge action with its own acknowledgement. App Store readiness and real-device performance remain distinct from compilation.

The optional SDK worker uses current Codex permission profiles instead of legacy sandboxMode because [official documentation](https://learn.chatgpt.com/docs/permissions) states those legacy settings override profiles. Its per-run configuration denies broad filesystem reads, allows only minimal tools and the candidate, and disables command network. [Official authentication documentation](https://learn.chatgpt.com/docs/auth) supports forced API login. A fresh per-run CLI configuration directory and explicit apiKey avoid borrowing a host session. Budget preflight estimates are recorded separately from reported token usage and measured spending is not fabricated.
