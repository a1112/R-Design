# R-Design 团队设计追溯与审批方案

用户于 2026-10-14 确认：借鉴 XD/Figma 的画布、图层与属性面板，优先追溯和审批；采用腾讯云团队服务并保留现有本地 Bridge。

## 产品与边界

团队入口提供真实账户、项目成员权限、设计版本、评论、审批队列和审计时间线。编辑器使用项目导航、图层树、中央可缩放画布、右侧属性/审批/追溯面板。设计版本从 PNG/JPEG/WebP 或本地工作台导出的真实截图与节点导入；可保留 XD/Figma 原始链接。首版不承诺原生 .xd/Figma 文件编辑，运行器仍在已授权本地工作空间隔离执行。

## 架构

- 保留 Express Bridge、候选变更与实际验证机制，合并并修复已有分支。
- 独立 `apps/team-server` 提供同源 `/api/team` 服务，使用 Node SQLite、密码哈希、HttpOnly 会话 cookie 和项目成员授权。
- 复用 React/Vite 工作台构建，`/team` 进入团队模式，本地主页和无限画布编辑器继续工作。
- 云端只保存设计快照、节点几何、版本摘要、差异与验证证据；不运行上传代码，不自动访问用户给出的 URL。
- SQLite 事务原子保存版本、审批、审计和幂等操作回执；数据库位于独立持久目录。

## 数据与审批

账户可加入项目，项目角色为 owner/designer/reviewer/viewer。设计版本内容和内容哈希不可修改；审批状态为 draft → in_review → approved/changes_requested。新修改创建新版本。提交和决策必须匹配最新版本的内容哈希与状态；禁止提交人自行审批。用户、成员变更、版本、评论和审批均写入服务端审计时间线，客户端不能填写操作者。

## 部署

腾讯云 `tencent-lighthouse` 已有其他项目占用 80/443。新增独立 release/data/config 目录及 systemd 服务，使用现有反向代理新增独立入口或空闲 TLS 端口。先检查域名与证书，复用有效可用证书或明确可用地址。保持现有服务配置；发布前构建测试，发布后核验真实 HTTPS、登录、权限拒绝和健康状态。管理员首个密码使用随机值，保存到被 Git 忽略的本地访问文件，不写入源码或日志。

## 验证

合并后运行完整单元/协议/安全测试与构建；团队服务测试真实 SQLite、鉴权、项目隔离、幂等、角色、审批旧版本/自审拒绝和重启持久化。浏览器验收登录、创建工程、上传真实设计快照、提交、另一账户审批、查看审计，以及本地已有工作台回归。
